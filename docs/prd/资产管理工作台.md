# 资产管理工作台

类型：概念（Concept） · 状态：当前实现反推

## 功能描述

为维护 Claude Code、Codex 项目配置的个人用户提供统一资产入口：创作资产、组织组合、导入项目已有内容、预览生效、记录历史和同步；以独立 Plugin 仓库维护完整用途包。

## 业务规则与约束

- 本版本以当前工作区真实行为为依据，含尚未提交的实现；不补写未实现路线图。
- 资产保存、项目生效、全库同步、Plugin 仓库操作各有独立完成结果，不能互相替代。
- 首页面向资产关系展示入口、数量与常用操作，侧栏进入各资产类别、项目、模型、审查配置、生效和同步。
- 目标软件为 Claude Code 与 Codex；各类别支持范围及本机条件由子节点明确。

## 交互流程和细节

**前置条件**：本机具备 Node.js 20+ 与 Git，启动本地应用并打开其网页。

1. 从首页或侧栏登记项目、配置模型，创作或导入资产。
2. 通过 Agent、套件与组组织已有资产，保存带说明的版本。
3. 为目标项目选择框架、模型及资产，先预览，再确认生效。
4. 查看项目当前配置和资产历史，记录问题、审查改进；按需同步全库或维护独立 Plugin。

**反馈与结果**：用户能区分“已保存”“本机选用历史”“已写入项目”“已同步”，并在各入口查看对应状态。

## 数据范围

可共享资产、资产历史、本机私有设置与问题记录、本机项目配置，以及独立 Plugin 包和历史。各范围是否同步由相应节点定义。

## 前置能力

本根节点无上层产品依赖，以下九个功能包共同覆盖当前范围；具体跨包引用见子文档。

## 边界情况与异常处理

- 本地服务默认允许局域网访问，没有应用内账号与角色权限隔离；当前行为不包含企业多租户权限管理。
- 依赖本机文件与运行环境的功能需在服务所在电脑可用，浏览器访问不意味着可操作访客电脑文件系统。
- 保存和生效错误、网络失败与模型返回不保证自动恢复，按各功能反馈处理；不将未核实成功的动作展示为已完成要求。

## 验收条件

- 总骨架九个直接子包均能定位到各自功能定义和验收条件。
- 从创作/导入、保存、预览生效到配置查看可串联完整使用路径。
- 版本本机选用与远端同步、Plugin 与全库资产的边界明确。
