# 原生Hook配置导入

类型：概念（Concept） · 状态：当前实现反推 · 核对日期：2026-10-18

## 功能描述

从 Claude Code 或 Codex 原生配置中逐项提取可支持的命令 Hook。

## 定位

所属功能包：[[docs/prd/资产管理工作台/事件自动化管理|事件自动化管理]]。本节点为原子能力，引用依赖与层级子节点分开维护。

- [[docs/prd/资产管理工作台/事件自动化管理/原生Hook配置导入|原生Hook配置导入]] [C] ●

## 业务规则与约束

- 一次选择最多 10 个文件，每个最多 500 KB；仅提取 Hooks，不导入其他配置。
- Claude 接受 settings.json、settings.local.json、插件 hooks.json；Codex 接受 hooks.json 及带内联 Hooks 的 config.toml。
- 按事件、分组、处理器逐项预览；每次确认独立保存版本，可跳过、暂停。相同内容可在再次选文件时跳过。
- 只支持 command，未知事件、类型和字段展示原因及原配置，不能直接保存；Codex Windows 命令覆盖等已支持信息保留。
- 导入不执行命令、不修改来源、不复制命令引用的外部脚本；跨项目需检查解释器、依赖和路径。

## 交互流程和细节

**前置条件**：应用已启动，用户进入上述功能入口；涉及已有资产时先选择资产。其余前置能力见下方引用。

1. 在 Hooks 点击导入配置并选择目标软件、文件。
2. 逐条检查命令、匹配、同步方式和超时。
3. 确认一条保存一条，或跳过、暂停；同名时按界面改名或登记新版本。

**反馈与结果**：混有可支持与不支持处理器时分别展示。

## 数据范围

原生配置文件中 Hooks 片段及命令信息。

## 边界情况与异常处理

- 不支持项保留原始预览和原因供跳过。
- 命令通过 Node 启动本机解释器，单独导入配置不构成完整脚本备份。

## 验收条件

- 混有可支持与不支持处理器时分别展示。
- 未点击确认的项不创建版本。
