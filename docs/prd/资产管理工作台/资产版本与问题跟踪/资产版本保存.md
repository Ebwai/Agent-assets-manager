# 资产版本保存

类型：概念（Concept） · 状态：当前实现反推 · 核对日期：2026-10-18

## 功能描述

为资产新增或修改建立带版本说明的历史记录。

## 定位

所属功能包：[[docs/prd/资产管理工作台/资产版本与问题跟踪|资产版本与问题跟踪]]。本节点为原子能力，引用依赖与层级子节点分开维护。

- [[docs/prd/资产管理工作台/资产版本与问题跟踪/资产版本保存|资产版本保存]] [C] ●

## 业务规则与约束

- 资产保存需填写去空白后至少 3 字、原始长度最多 10000 字的版本说明；名称不能为空。
- 保存按资产类型执行校验；正在解决全库同步冲突时阻止资产版本写入。
- 从本机选用旧版本进入编辑后保存，基于当前仓库最新历史产生一个新版本，不重新提交旧版本本身。
- 保存成功清除该资产的本机历史选用状态，返回最新内容；问题记录仅在本次成功版本中关联所选条目。
- 资产保存与向项目生效是独立动作，保存不自动改写已部署配置。

## 交互流程和细节

**前置条件**：应用已启动，用户进入上述功能入口；涉及已有资产时先选择资产。其余前置能力见下方引用。

1. 新建或编辑资产，点击保存版本。
2. 在弹窗填写说明，可选择已完成问题追加说明。
3. 确认后检查成功反馈与版本历史；失败时修正原因后重试。

**反馈与结果**：说明少于 3 字时不产生新版本。

## 数据范围

各类别资产内容、创建与更新时间、说明和历史版本。

## 前置能力

- ⇢ [[docs/prd/资产管理工作台/资产版本与问题跟踪/问题记录与版本关联|问题记录与版本关联]]

## 边界情况与异常处理

- 字段不合法、缺失依赖或说明不合法时显示原因。
- Git 保存失败不能视为已创建版本；文档不承诺对所有本机写入提供事务回滚。

## 验收条件

- 说明少于 3 字时不产生新版本。
- 编辑旧版保存后新增一个版本，可继续查看原历史。
