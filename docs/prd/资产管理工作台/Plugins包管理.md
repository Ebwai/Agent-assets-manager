# Plugins包管理

类型：概念（Concept） · 状态：当前实现反推

## 功能描述

管理包含完整文件的用途包，并区分上游接收、自用修改与对外推送。

## 业务规则与约束

包使用独立历史；他人默认分支只读，自用修改在自己的分支，快照和全库源资产相互独立。

- [[docs/prd/资产管理工作台/Plugins包管理/Plugin来源接入与资料|Plugin来源接入与资料]]：以完整用途包为单位，新建本地包、导入本地目录或连接自有/他人 GitHub 仓库。
- [[docs/prd/资产管理工作台/Plugins包管理/Plugin文件与资产快照|Plugin文件与资产快照]]：查看编辑完整包文件，并识别包内资产或放入全库资产的独立快照。
- [[docs/prd/资产管理工作台/Plugins包管理/Plugin版本与上游更新|Plugin版本与上游更新]]：查看包历史和 Release，比较上游变化并按需接收更新。
- [[docs/prd/资产管理工作台/Plugins包管理/Plugin分支与推送|Plugin分支与推送]]：隔离他人上游与自己的修改，并将自用分支推送至自有仓库或 Fork。
- [[docs/prd/资产管理工作台/Plugins包管理/Plugin自用分支融合与冲突|Plugin自用分支融合与冲突]]：更新上游后把自己的提交接到新版基础上，并人工处理 rebase 冲突。

## 交互流程和细节

**前置条件**：应用已启动；各子能力的具体入口、前置条件及反馈见对应文档。

用户接入包，浏览文件和资产，保存版本，检查更新并在自用分支融合和推送。

**用户可观察结果**：完成对应子能力的操作后，获得该子能力定义的内容、记录或错误反馈；父功能包不增加额外隐含操作。

## 数据范围

完整包文件、分支、Release 和本机包资料。

## 前置能力

无独立前置功能包；由所属上层能力触发。

以上为下属能力使用的外部引用汇总，并非进入整个父功能包必须一次配置全部依赖；按具体操作按需满足。

## 边界情况与异常处理

普通更新不覆盖分叉历史；冲突进入独立 rebase 流程，可继续或取消。

各子能力的限制和异常结果由其节点定义；组合使用时同时遵循必要引用节点的规则。
