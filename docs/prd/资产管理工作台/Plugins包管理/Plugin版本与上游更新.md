# Plugin版本与上游更新

类型：概念（Concept） · 状态：当前实现反推 · 核对日期：2026-10-18

## 功能描述

查看包历史和 Release，比较上游变化并按需接收更新。

## 定位

所属功能包：[[docs/prd/资产管理工作台/Plugins包管理|Plugins包管理]]。本节点为原子能力，引用依赖与层级子节点分开维护。

- [[docs/prd/资产管理工作台/Plugins包管理/Plugin版本与上游更新|Plugin版本与上游更新]] [C] ●

## 业务规则与约束

- 版本页突出正式 Release，区分预发布和 Commit 更新；最多展示当前分支最近 30 条历史。
- Release 采用状态按默认分支是否包含标签提交判断，不按标题或当前自用分支猜测。
- 检查远端后可预览默认分支与上游分支差异；Release 查询失败单独提示，不隐藏 Commit 更新。
- 默认分支更新仅允许快进，更新后返回原自用分支；分叉时停止，不覆盖已有提交。
- 包历史差异比较所选提交与第一父提交，首次为新增，不受当前工作区影响；恢复历史需说明并创建新提交。

## 交互流程和细节

**前置条件**：应用已启动，用户进入上述功能入口；涉及已有资产时先选择资产。其余前置能力见下方引用。

1. 进入版本与更新，检查远端，阅读 Release 和 Commit 更新。
2. 预览上游差异；选择更新默认分支或进入自用分支 rebase。
3. 查看历史差异，必要时确认恢复历史内容并填写说明。

**反馈与结果**：Release 查询失败时仍显示可用的 Commit 更新。

## 数据范围

当前分支提交、标签、远端 Release、默认分支和上游差异。

## 前置能力

- ⇢ [[docs/prd/资产管理工作台/Plugins包管理/Plugin分支与推送|Plugin分支与推送]]

## 边界情况与异常处理

- 私有 Release 可借本机已登录 GitHub CLI 查询，失败提示登录或查询错误。
- 有未提交内容先保存；上游默认分支变更要求先检查仓库设置。

## 验收条件

- Release 查询失败时仍显示可用的 Commit 更新。
- 更新默认分支后当前自用分支内容保持原状态，直到 rebase。
