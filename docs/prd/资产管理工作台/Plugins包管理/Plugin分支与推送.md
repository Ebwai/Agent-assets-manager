# Plugin分支与推送

类型：概念（Concept） · 状态：当前实现反推 · 核对日期：2026-10-18

## 功能描述

隔离他人上游与自己的修改，并将自用分支推送至自有仓库或 Fork。

## 定位

所属功能包：[[docs/prd/资产管理工作台/Plugins包管理|Plugins包管理]]。本节点为原子能力，引用依赖与层级子节点分开维护。

- [[docs/prd/资产管理工作台/Plugins包管理/Plugin分支与推送|Plugin分支与推送]] [C] ●

## 业务规则与约束

- 他人包的默认分支仅接收上游，页面和服务端都禁止在其上保存、提交和推送；需先创建或切换自用分支。
- 自有仓库允许修改默认分支；本地包可后续关联自己的 GitHub 仓库。
- 切分支和关联远程前工作区需干净且不在 rebase 中。
- 他人包必须关联不同于上游的自有 Fork；提供 GitHub 创建 Fork 入口，不自动创建 Fork。
- 推送使用系统 Git 凭据，不自动强推；可新建分支后推送，已推送分支 rebase 后建议新分支推送。

## 交互流程和细节

**前置条件**：应用已启动，用户进入上述功能入口；涉及已有资产时先选择资产。其余前置能力见下方引用。

1. 进入仓库与同步，创建或切换自己的分支。
2. 完成编辑保存后，填写自有仓库或 Fork 链接。
3. 选择推送当前分支或新建分支推送，检查成功反馈。

**反馈与结果**：他人默认分支直接保存和推送均被拒绝。

## 数据范围

包分支、上游/推送地址、归属和工作区状态。

## 前置能力

- ⇢ [[docs/prd/资产管理工作台/Plugins包管理/Plugin来源接入与资料|Plugin来源接入与资料]]

## 边界情况与异常处理

- 无推送地址、无有效分支、工作区未提交或默认分支保护时明确阻止。
- 认证失败或远端拒绝时保留错误，要求用户处理后重试。

## 验收条件

- 他人默认分支直接保存和推送均被拒绝。
- 切自用分支后可保存并推送到另一个仓库。
