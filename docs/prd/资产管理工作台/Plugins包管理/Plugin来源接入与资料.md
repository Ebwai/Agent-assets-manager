# Plugin来源接入与资料

类型：概念（Concept） · 状态：当前实现反推 · 核对日期：2026-10-18

## 功能描述

以完整用途包为单位，新建本地包、导入本地目录或连接自有/他人 GitHub 仓库。

## 定位

所属功能包：[[docs/prd/资产管理工作台/Plugins包管理|Plugins包管理]]。本节点为原子能力，引用依赖与层级子节点分开维护。

- [[docs/prd/资产管理工作台/Plugins包管理/Plugin来源接入与资料|Plugin来源接入与资料]] [C] ●

## 业务规则与约束

- 包有独立名称、说明和仓库，独立于全库资产同步；资料和仓库关联保存在本机索引。
- 归属分本地、自有、他人；远程包需有效 GitHub 地址，不能同时选本地目录和远程。
- 本地导入保留二进制，跳过 .git，拒绝链接及特殊文件；最多 64 MB、10000 项、20 层目录。
- 包内脚本不会自动执行；导入失败不保留半成品包。

## 交互流程和细节

**前置条件**：应用已启动，用户进入上述功能入口；涉及已有资产时先选择资产。其余前置能力见下方引用。

1. 进入 Plugins，新建并填写名称、说明和归属。
2. 选择本地空包、目录或 GitHub 地址。
3. 完成后查看文件、资产、版本与仓库同步；可修改名称说明。

**反馈与结果**：目录导入后文件字节保持一致且无来源 .git。

## 数据范围

完整包文件、自有/他人归属、来源及本机索引。

## 前置能力

无独立前置功能包；由所属上层能力触发。

## 边界情况与异常处理

- 远程无可用默认分支、目录不合法或超过范围显示错误。
- 不导入包含 Plugin 数据自身的目录，避免重复收录。

## 验收条件

- 目录导入后文件字节保持一致且无来源 .git。
- 包的提交不出现在全库资产历史中。
