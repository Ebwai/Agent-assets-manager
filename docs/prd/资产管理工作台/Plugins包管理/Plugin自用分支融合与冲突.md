# Plugin自用分支融合与冲突

类型：概念（Concept） · 状态：当前实现反推 · 核对日期：2026-10-18

## 功能描述

更新上游后把自己的提交接到新版基础上，并人工处理 rebase 冲突。

## 定位

所属功能包：[[docs/prd/资产管理工作台/Plugins包管理|Plugins包管理]]。本节点为原子能力，引用依赖与层级子节点分开维护。

- [[docs/prd/资产管理工作台/Plugins包管理/Plugin自用分支融合与冲突|Plugin自用分支融合与冲突]] [C] ●

## 业务规则与约束

- 先更新默认分支，再将当前自用分支 rebase 到更新后内容；不允许在默认分支发起。
- 开始前需保存工作区；发生冲突时保持可处理状态，普通保存/推送受阻。
- 冲突文件逐个编辑或按删除处理，全部解决后继续；可以取消 rebase 恢复自用分支原状态。
- 融合与冲突编辑不自动执行包脚本。

## 交互流程和细节

**前置条件**：应用已启动，用户进入上述功能入口；涉及已有资产时先选择资产。其余前置能力见下方引用。

1. 在自用分支点击更新并 rebase。
2. 出现冲突时逐个查看、编辑或选择删除并标记解决。
3. 继续融合；若再有冲突重复处理，或选择取消。

**反馈与结果**：取消后自用分支恢复 rebase 前状态。

## 数据范围

上游新版、自用提交、冲突文件及用户解决内容。

## 前置能力

- ⇢ [[docs/prd/资产管理工作台/Plugins包管理/Plugin版本与上游更新|Plugin版本与上游更新]]

## 边界情况与异常处理

- 默认分支已分叉不能快进时停止更新。
- 冲突内容超过 2000000 字节或目标不是冲突文件时拒绝保存解决。

## 验收条件

- 取消后自用分支恢复 rebase 前状态。
- 解决冲突继续后，自用提交在新版上游基础上可见。
