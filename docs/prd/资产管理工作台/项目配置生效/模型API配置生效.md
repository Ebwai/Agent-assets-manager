# 模型API配置生效

类型：概念（Concept） · 状态：R13 已实现 · 核对日期：2026-10-21

## 功能描述

将已保存模型服务应用为 Claude Code 或 Codex 的自定义 API，并可恢复之前的配置。

## 定位

上层：[[docs/prd/资产管理工作台/项目配置生效|项目配置生效]]。本节点为原子能力。

## 业务规则与约束

- Claude Code 使用 Messages 兼容端点，Codex 使用 Responses 兼容端点；两者均仅配置本机用户级 API，影响使用该配置的新会话，不提供项目选择。
- 主协议与目标不兼容时需填写对应外部网关地址，否则显示原因并阻止应用；不将任意上游地址直接当成兼容地址。
- 使用已保存模型版本，变更地址、模型或密钥后需先保存；API 配置与资产内容匹配分别操作。
- 从供应商已保存模型列表中选择目标软件使用的模型，允许与资产 AI 辅助模型不同，应用不修改 AI 设置及资产组合引用。
- 应用窗口可勾选目标软件列表中的模型、修改显示名。Claude Code 配置家族别名、子任务默认模型和可选的完整版本 ID 映射；支持的客户端显示自定义列表。Codex 列表使用真实供应商 ID，可设置上下文与推理参数，审查模型也必须在列表内。
- 上次应用的映射保存在本机并在相同供应商重新打开时回填。显示名不会隐式改变请求模型。已有聊天、显式 Agent 模型、profile、项目覆盖与组织策略仍可能优先。
- 应用与撤销均先预览实际位置、作用范围、脱敏前后内容，再由用户确认；预览不写文件。
- 密钥继续由本机私有存储提供，目标配置引用凭据辅助程序；修改 Key 后辅助程序读取最新值，删除 Key 后认证失败。
- 预览后配置、模型或密钥变化则要求重新预览。助手管理的字段被外部修改时停止覆盖及撤销；其他字段保留。
- 重复应用不叠加配置；撤销恢复原有受管字段，没有其他改动时恢复原始文件文本或文件不存在的状态。
- 用户级应用会预览并清理已登记项目中旧版助手管理的 Claude API 覆盖，恢复原字段并保留无关设置；受管字段被外部修改时停止迁移。其他手工项目覆盖仍可能优先于用户设置。

## 交互流程和细节

1. 在模型服务编辑页点击「应用 / 撤销用户级 API」。
2. 选择 Claude Code 或 Codex，以及应用或撤销；应用时选择默认模型、列表及其映射，无需项目路径。
3. 点击「预览配置与映射」，查看对应关系、目标位置、作用范围、主配置及目录文件变化。
4. 确认应用／撤销；完成后重新启动目标软件并检查实际服务连接。

## 数据范围

已保存模型定义、本机密钥、目标软件配置、本机受管字段原值及凭据辅助程序。恢复信息不参与远程同步。

## 边界情况与异常处理

- 现有配置损坏、路径不安全或受管字段被改动时拒绝写入并说明原因。
- 环境变量、启动参数或组织策略可能覆盖生成的设置；服务需满足目标软件的工具调用与流式能力，助手文本测试不能证明完整 Agent 会话兼容。
- 两种软件均不新建项目级 API 配置；界面显著说明用户级影响范围。
- Claude Code 完整自定义列表需要 2.1.242+，旧版使用家族别名及单个自定义选项；版本映射也受客户端支持范围限制。Codex 本地目录不改变 ChatGPT 云端聊天模型。
- Codex 目录使用保守文本／函数工具能力，上下文默认 32768，默认不发送推理参数；用户应按服务能力调整。目录最大 1 MiB，超限需减少选中模型。
- 应用会重新序列化配置；当原 TOML 存在无关外部修改时，撤销保留其语义，但不保证保留注释与排版。

## 验收条件

- R13：应用窗口可调整目标模型列表和名称；Claude 别名与指定版本映射可配置，Codex 目录 ID 与实际请求一致，不能只验证默认模型文本响应。
- 模型目录的新增／更新／撤销纳入预览、并发保护和失败回滚；重新应用及撤销保留原有无关配置。客户端不支持完整列表时明确展示版本要求，不宣称旧聊天已切换。

- 两种软件的预览零写入，确认后文件使用正确协议与范围，不嵌入 Key。
- 受管配置可重复应用与撤销，保留无关手动修改，预览过期或受管字段被改动时拒绝覆盖。
- 多模型供应商可分别选择 AI 模型及外部软件模型；旧项目覆盖迁移包含在同次预览与确认中。
