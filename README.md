# Agent 资产管理助手

本地运行的网页应用。资产库位于用户目录下的 `Agent_assets_manager/repo`，每次保存资产都会创建 Git 提交。首次启动会从旧版项目内的 `.asset-data` 迁移资产库及其完整历史。模型密钥、本机项目路径、MCP 环境变量和本机选用的历史版本保存在 `Agent_assets_manager/private`，不参与 Git 同步。

## 启动

需要 Node.js 20+ 和 Git。Windows 可双击 `启动助手.cmd`（首次运行会安装依赖）；也可以先运行 `npm install`，再运行 `npm start`，打开终端显示的 `http://127.0.0.1:8073`。可用 `PORT` 环境变量改端口。

## Plugins

左侧「Plugins」管理服务于同一用途的完整包，可新建本地包、导入本地目录，或连接自己 / 他人的 GitHub 仓库。包可包含 Skills、Rules、提示词、Agent、Hooks、套件、模型定义等资产，也可包含其他脚本、配置与二进制文件。脚本不会自动执行。每个包有独立 Git 仓库，位于 `Agent_assets_manager/plugins/<ID>`，与整个资产库的远程同步分开；包名称、说明与仓库关联记录保存在本机的 Plugins 索引中。

- 「文件」查看完整内容、编辑文本、上传文件 / 文件夹、删除文件；保存时填写版本说明并创建提交。上传每次最多 12 MB；本地目录导入最多 64 MB，跳过 `.git`，拒绝链接和特殊文件。二进制文件保留原始字节，可上传替换；在线文本编辑最多 2 MB。被 `.gitignore` 排除的新文件不能作为版本保存。
- 「资产」识别原生项目路径与插件的 `skills/`、`rules/`、`agents/`、`hooks/hooks.json`；也可从资产库放入资产快照，保存在 `.plugin-assets/<类型>/<ID>.json`。包内快照独立于原资产，修改来源文件会形成新的包版本，不会自动回写原资产。项目本机目录和审查配置不作为包内资产；模型密钥及 MCP 本机环境变量不复制。
- 「版本与更新」显著展示正式 Release，区分预发布和 Commit 更新，支持检查远端、预览上游差异、查看当前分支提交历史、与历史比较，以及恢复历史内容并创建新提交。Release 是否采用以默认分支是否包含对应标签提交判断。公开 Release 使用 GitHub API；私有仓库可使用本机已登录的 GitHub CLI 查询，查询失败会单独提示，不隐藏 Commit 更新。
- 他人项目的默认分支只用于接收上游更新，页面和服务端均禁止在其上保存、提交或推送自己的修改。编辑前在「仓库与同步」创建 / 切换自己的分支。默认分支只能快进更新，若被外部工具改出分叉则停止更新，不覆盖已有提交。
- 「更新默认分支」获取上游后更新默认分支，保留当前自己的分支；「更新并 rebase 自己的分支」先更新默认分支，再将自己的提交接到新版上。工作区有未提交修改时先在自己的分支提交。冲突可以逐个编辑或按删除处理，再继续；也可取消 rebase，恢复自己分支的原状态。
- 为他人项目关联自己的 Fork 链接后，可以推送自己的分支；页面提供 GitHub 创建 Fork 的入口。也可选择新建分支后推送。推送使用系统 Git 身份凭据，不自动强制推送；对已经推送过的分支进行 rebase 后，建议创建新分支推送。自己的仓库允许修改默认分支，本地包也可后续关联自己的 GitHub 仓库。


## 使用

1. 在「项目」里登记项目，点击「选择文件夹」打开系统目录选择窗口。本机目录可稍后分配，且不会上传远程。新电脑载入项目后会显示待分配路径。
2. 创建 Skill、套件、提示词层和 Agent 时，先选择 Harness 框架与模型服务中的模型版本。一个资产可保存多个组合的微调内容，每次保存都填写版本说明。新建 Skill 时可点「从本地目录导入」，选择包含 `SKILL.md` 的单个 Skill 文件夹，确认解析预览后编辑或直接保存为 Git 版本。`scripts/`、`references/`、`assets/` 中的文件会一并带入。
3. 在「模型服务」配置供应商名称、API 协议、地址和 API Key，获取或手工维护多个模型 ID，再选择资产 AI 辅助使用的模型。支持 Anthropic Messages、OpenAI Chat Completions、OpenAI Responses、Gemini generateContent；本地服务可选择无需密钥。「测试 AI 辅助模型连接」可验证未保存草稿，审查、改进及画板 AI 功能使用指定模型。
4. 在「生效」选择 Harness 框架与模型版本，再选择该组合可用的资产、预览目标文件，确认后写入项目目录。Claude Code 使用 `.claude/skills` 和 `CLAUDE.md`；Codex 使用 `.agents/skills` 和 `AGENTS.md`。
5. 在「远程同步」连接一个 GitHub 仓库，再点「一键同步」。新电脑连接同一仓库会载入资产和完整历史。两台电脑修改同一资产时，页面会要求逐项选择本机或远程内容。

在版本历史中点击「在本机使用」只改变这台电脑的当前资产内容，不会产生提交。编辑后点击「保存版本」才会基于仓库最新提交创建一个新版本。旧版本本身不会被重新提交。

### Claude Code / Codex 自定义 API

保存供应商模型服务后，在编辑页点击「应用 / 撤销用户级 API」，选择目标软件及其使用的模型，再预览、确认。两种软件均配置本机用户级，无需选择项目。目标软件模型从已保存列表选择，可以与资产 AI 辅助模型不同，互不修改；普通资产生效中选择模型服务仅匹配资产内容，不会隐式切换软件 API。

- Claude Code：将地址、模型和凭据辅助命令写入本机 `$CLAUDE_CONFIG_DIR/settings.json`（默认 `~/.claude/settings.json`），保留其他配置。主服务需为 Messages 协议，或在兼容选项中填写 Messages 网关地址。已登记项目中的旧版助手 API 覆盖会列入预览并在确认后恢复，受管字段被外部修改时停止迁移。
- Codex：写入本机 `$CODEX_HOME/config.toml`（默认 `~/.codex/config.toml`）的自定义 provider，使用 Responses 协议；这是用户级配置，影响使用它的新会话，预览会明确显示。主服务为其他协议时需填写 Responses 网关地址；项目级 provider 不会生效。
- 供应商模型列表支持「从 API 获取模型列表」及手工增删，每行一个 ID；获取结果会合并到草稿，不自动保存。目标网关使用本服务的同一 Key；若 Key 不同，请另建服务。应用不内置完整协议转换网关，使用 New API 等服务提供的兼容端点即可接入其他上游。
- Key 不写入目标配置，认证辅助程序从助手私有目录读取；换电脑需重新保存 Key 并应用。环境变量、启动参数及组织策略可能覆盖配置，应用后请重新启动软件并检查连接。
- 「撤销助手配置，恢复原值」也需先预览确认；受管字段被外部修改时停止覆盖。原配置及恢复信息仅保存在助手私有目录。TOML 应用会重新排版；没有外部修改时撤销还原原始文本，有无关修改时保留其语义。

连接测试仅验证文本调用。目标网关及模型还需兼容目标软件的流式输出、工具调用和上下文处理，不能把一次返回文本视为完整 Agent 兼容认证。旧模型未设置协议时仍按 Anthropic 处理；旧单模型服务兼容为单元素列表，保留原服务和资产引用。

生效时，`CLAUDE.md`（Claude Code）或 `AGENTS.md`（Codex）使用本次选定的提示词、Agent 指令和套件说明覆盖整个文件；旧原文、旧管理区块及区块外文字会被替换，预览标明「覆盖全部内容」。重复生效不会追加。仅应用 Rules 时仍按 Rules 的写入范围处理。Skill 目录按当前资产版本更新；若目标位置已有非本助手管理的同名 Skill，会阻止覆盖。Claude Code 的允许工具写入 `.claude/settings.json` 的 `permissions.allow`，MCP 写入项目根目录 `.mcp.json`；Codex 的工具清单作为 Agent 指令，MCP 写入 `.codex/config.toml`。请在目标软件重新加载项目配置。

## 待解决问题

每个资产编辑页都有「待解决问题」板块。用一个自由文本区域快速记录问题或修改想法，之后可编辑、删除、勾选完成或重新打开；添加记录无需填写版本说明，不创建资产 Git 版本。新资产首次保存后即可使用。

保存资产版本时，弹窗列出已完成且尚未纳入版本的问题，点击逐条追加到版本说明，可继续编辑和补充多行文字。未选的问题保留到下次；取消或提交失败不会关联版本。提交成功后记录对应的 Git 版本和当时的问题文字；重新打开并再次完成可关联新的版本，保留此前记录。

问题记录位于本机 `Agent_assets_manager/private/asset-issues`，不参与远程同步。切换资产历史版本、删除并恢复资产不会回退或清空这些记录；发现问题时关联当时本机正在使用的版本。

## Hooks

在左侧「Hooks」新建命令脚本资产，选择目标软件、触发事件、匹配条件、同步或异步、超时与入口脚本。Hooks 适用于所选软件的所有模型，不需要配置模型服务。支持 Node.js、Python、PowerShell 和 Bash；目标电脑需安装对应运行环境。每个资产可包含多个文本脚本，保存版本、选用历史版本、删除恢复和远程同步与其他资产一致。

1. 编辑 `scripts/` 中的脚本，或导入现有文本脚本。默认提供 Node.js 示例；更换事件后可点击「填入 Node.js 示例」。脚本从标准输入读取事件 JSON，通过退出码或标准输出返回结果。
2. 点击「检查与预览配置」检查基础格式。使用「模拟测试」传入示例事件，可查看匹配结果、退出码、输出、错误及耗时。测试会真实运行脚本，默认使用临时工作目录；选择项目后使用其本机目录。最多等待 30 秒，并限制输出大小。模拟测试不启动 Agent，也不完全模拟各软件的输出校验和执行规则。
3. 在 Agent 配置中关联 Hooks，或在「一键生效」直接勾选。只应用 Hooks 时可不选择模型。先预览，再确认写入项目。
4. Claude Code 配置合并到 `.claude/settings.json` 的 `hooks`；Codex 配置合并到 `.codex/hooks.json`。脚本分别写入 `.claude/hooks/asset-manager/<资产 ID>/` 和 `.codex/hooks/asset-manager/<资产 ID>/`。管理记录位于 `.agent-asset-manager/<软件>.json`。重复生效不会重复添加条目；取消勾选后再次生效会移除助手管理的条目和文件，保留原有外部 Hooks。Agent 关联的 Hooks 会随 Agent 一并应用，移除时也需解除关联或取消选择 Agent。若管理条目或脚本在项目中被修改，会停止覆盖并提示先保存修改。

同步脚本在触发点执行，Agent 等待其结束；异步脚本在后台运行，返回的控制决定不能阻止当前操作。同一事件的多个脚本由目标软件调度，不应依赖先后顺序。Codex 的会话结束事件只能同步运行，会话结束及中断事件最多等待 3 秒。

写入配置后，在目标软件中检查 `/hooks`；Codex 新增或修改的 Hooks 需要审查并信任。项目脚本使用本机绝对路径，换电脑或移动项目后需重新生效。本版管理项目级 command Hooks，用户级配置、HTTP、MCP、prompt 和 agent 类型尚未接入。保存资产不会执行脚本；自动事件只在目标软件运行时触发，Codex 云端任务不支持本地命令 Hooks。

事件输入输出以目标软件版本为准：[Claude Code 官方说明](https://code.claude.com/docs/en/hooks)、[Codex 官方说明](https://learn.chatgpt.com/docs/hooks)。

## 单个 Hook 与 Hooks 组

Hooks 导航分为「单个 Hook」和「Hooks 组」。单个 Hook 保存事件、匹配条件、脚本和执行设置。Hooks 组填写共同用途，选择适用于同一软件的多个现有 Hook，可为每个成员补充作用说明；组引用成员，不复制脚本。组不绑定模型，沿用资产 Git 版本、历史选用、删除恢复和同步机制。

Agent 可同时关联单个 Hook 和 Hooks 组；「一键生效」也可整组选用。生效时展开组内成员，与直接选中的 Hook 和 Agent 关联去重。同一成员出现在多个组中也只部署一次。组内列表不是执行顺序，实际触发仍由每个 Hook 的原生事件和匹配条件决定。项目当前配置资产视图同时记录应用的组版本和成员版本。

修改组成员或取消选择组后再次生效，会更新实际部署；仍被其他组、Agent 或单独选择引用的成员会保留。成员被删除或目标软件不匹配时，预览会报告问题，组仍可编辑修复。

## 导入原生 Hooks 配置

在 Hooks 页面点击「导入 Hooks 配置」，先选 Claude Code 或 Codex，再选择一个或多个文件（最多 10 个，每个最多 500 KB）。Claude Code 可选 `settings.json`、`settings.local.json` 或插件 `hooks.json`；Codex 可选 `hooks.json` 或含内联 Hooks 的 `config.toml`。仅提取 hooks，不导入模型、权限等其他设置。

按事件、分组和处理器逐项展示原配置、命令、匹配条件、同步/异步及超时。每次点击「确认导入这一项」才保存一个 Git 版本，支持跳过和暂停；再次选择文件时，会跳过资产库中内容相同的 Hook。当前支持 command 类型，其他类型、未知事件或尚未支持的字段会显示原因和原配置，不能直接保存。Codex 的 Windows 命令覆盖、状态提示和上下文长度限制会保留。

导入不执行命令，不改写来源文件，也不复制命令所引用的脚本。命令通过 Node 启动本机默认解释器；目标电脑需有 Node，应用前需检查原命令的解释器、路径和依赖。命令引用外部文件时，单独导入配置不能成为完整脚本备份。

格式参考：[Claude Code Hooks](https://code.claude.com/docs/en/hooks)、[Codex Hooks](https://learn.chatgpt.com/docs/hooks)。

## Claude Code Rules

「Rules」管理 Claude Code 的 Markdown 行为规范，不绑定模型。填写名称、规则文件名和正文；适用文件每行填写一条相对于项目根目录的 glob，留空表示整个项目。应用时自动生成 `paths` YAML。此类别不提供搜索、分类或模板，`CLAUDE.md`、`AGENTS.md` 仍由系统提示词功能管理。

可导入一个或多个 `.md` 规则文件，也可选择 `.claude/rules` 中的 `rules` 文件夹，预览并勾选后导入。单条规则进入编辑器等待保存；多条规则填写版本说明后逐条保存。导入会解析 `paths`，并提示 Claude Code 不识别的其他 YAML 字段。规则正文和文件路径经过基础格式检查；保存、历史版本选用、删除恢复、远程同步沿用资产版本机制。

Claude Code Agent 可关联 Rules；项目可配置默认 Rules，也可在「一键生效」直接选择。只应用 Rules 时无需模型。生效会去重，并将文件写入 `.claude/rules/asset-manager/<资产 ID>/<规则文件名>`，保留外部规则。移除时取消直接选择及 Agent 关联，再次生效；项目默认关联不会自动修改已经写入的文件。项目中手动修改了助手管理的规则时，会停止覆盖或移除并提示处理修改。仅应用 Rules 不改写既有系统提示词文件。

## 导入项目现有资产

在「项目」选择本机文件夹后，已保存的项目会自动识别现有资产；新项目在首次保存后开始。弹窗每次展示一项，包含来源、内容、配置和资源预览，可修改名称、选择模型版本（可选）及版本说明，再点击「确认导入这一项」。每次确认独立保存 Git 版本。扫描本身不保存资产、不执行 Hook，也不修改项目原文件。

支持项目根目录的 `CLAUDE.md`、`CLAUDE.local.md`、`AGENTS.md` 和 `.claude/CLAUDE.md`；`.claude/skills`、`.agents/skills`、`.codex/skills` 中的 Skills 与 scripts/references/assets 资源；`.claude/rules` 中的 Claude Rules；`.claude/agents` 中的指令与工具；以及 `.claude/settings.json`、`.claude/settings.local.json`、`.codex/hooks.json` 中的 command Hooks。原生子 Agent 的其他字段会提示未转换，不能视为完整备份。命令 Hook 保留原命令并通过 Node 启动本机命令解释器；命令引用的项目脚本不会复制，跨项目使用前需检查依赖与相对路径。其他类型 Hook 和不支持的字段显示原因，供用户跳过。

可「跳过这一项」或「稍后继续」，随后从项目页「识别 / 继续确认」继续；「重新查看已跳过项」允许再次选择。同一项目和路径下已经确认的相同内容不会重复导入；源内容变动后重新等待确认，导入为新资产。来源变化时拒绝旧预览确认。记录只保存在本机 private 目录，不同步项目路径。已由助手管理的目录、提示词区块和 Hook 配置不会重复收录。

仅扫描上述项目资产位置，不读取用户级配置、链接目录或项目外文件；最大 3000 个扫描文件、500 个资产、64 MB 读取内容，Skill 资源最多 12 MB。未关联模型的原生资产可先导入，之后编辑保存时按现有资产编辑器选择 Harness 和模型。导入完成后不会自动关联默认规则或重新部署，项目原配置继续保留。

## 查看项目当前配置资产

在「项目」选择已分配本机路径的项目，即可查看「当前配置资产」并刷新。视图展示 Claude Code 和 Codex 的实际生效记录：Agent、Skills、套件、提示词、Hooks、Rules，及应用版本、时间、所选模型、工具和 MCP 名称。也会检查写入文件是否与生效时一致、被修改或缺失，并列出未由助手管理的项目 Rules 文件。

视图依据本机项目的生效记录，不将默认关联误显示为已应用，也不显示密钥和 MCP 环境变量。它不能证明目标软件已加载这些配置，不包含用户级配置。旧记录缺少的 Agent、模型和版本信息会标明未知，后续再次生效时补齐。

本应用默认监听 `0.0.0.0:8073`，同一局域网的设备可打开 `http://运行电脑的局域网IP:8073`，具体地址会在启动终端显示。若无法连接，请在 Windows 防火墙中允许 Node.js 或 TCP 8073 的专用网络入站访问。局域网访客拥有完整操作权限，仅在可信网络使用，请勿将端口映射到公网。API Key 在本地明文文件中保存，目录仅供当前机器使用。GitHub 身份凭据由系统的 Git 凭据管理器处理，本应用不保存 GitHub 令牌。建议使用私有仓库。若旧版资产的 Git 历史曾保存本机路径或 MCP 环境变量，应用会阻止远程同步，以免将历史中的敏感内容上传。

版本差异按所选版本与该资产的上一个历史版本比较；插件按所选提交与第一父提交比较，不受当前工作区修改影响。首次版本显示为新增。差异界面只列变化文件，Skill 正文与 scripts / references / assets 分别显示，配置仅显示变化项；删除为红色、新增为绿色，并高亮行内变化。未变化内容默认折叠，可展开上下文或跳转上一处 / 下一处变化。上游更新预览仍比较本机默认分支与上游分支，并使用同一差异界面。
